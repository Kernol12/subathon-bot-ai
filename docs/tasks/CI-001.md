## Recovery contract revision 2

The standard-library Python helper gets its own named step immediately after checkout
and before any package operation in all nine Ubuntu24.04 APT lanes (SQL fixture reproduction
may remain before it). It requires GITHUB_ACTIONS=true, RUNNER_ENVIRONMENT=github-hosted and
platform.freedesktop_os_release() reporting ID=ubuntu, VERSION_ID=24.04 before
any commands or writes (missing ID/VERSION_ID also refuses). Guard refusal raises RuntimeError with separate specific
messages: "requires GitHub-hosted Actions", "requires Ubuntu 24.04". Failure to read
OS identity is an OSError surfaced by main; no commands or writes follow.

Read only /etc/apt/sources.list.d/ubuntu.sources through Path.read_text(encoding="utf-8").
A nonempty file must contain at least one non-comment stanza; every stanza must have exactly one URIs field containing only
mirror+file:/etc/apt/apt-mirrors.txt. Blank lines, CRLF and comment lines are accepted;
missing/duplicate/mixed/continued URIs, alternate files, third-party stanzas and
Enabled: no/other unknown layouts are refused with RuntimeError containing
"unsupported Ubuntu APT source layout", before commands/writes. Missing file remains
an OSError, surfaced by main. Other source files are preserved, not rewritten or
printed: strict update intentionally fails if any configured repository is unavailable,
including the runner's Microsoft repository. It never silently drops a repository.

Run exactly these best-effort diagnostics before privileged writes: cat /etc/resolv.conf;
resolvectl status; cat /etc/apt/apt-mirrors.txt; getent ahostsv4 for each of
azure.archive.ubuntu.com, archive.ubuntu.com, security.ubuntu.com and
mirrors.edge.kernel.org. Each uses
subprocess.run(check=False, capture_output=True, text=True, timeout=10), without a
shell. Print "Diagnostic only; not dependency admission", each full command with
"<command>: exit <code>" or "<command>: unavailable <error>", and its captured
stdout/stderr. Missing commands and timeout are reported and do not decide success.
Do not dump other source files or environment variables. No DNS-server configuration
is changed. The only privileged commands, in order, are the two tee writes and one
sudo apt-get update below; no other subprocesses/install/resolver commands are allowed.

Through checked sudo tee, replace only /etc/apt/apt-mirrors.txt with these literals (a literal tab before each priority):

```text
https://mirrors.edge.kernel.org/ubuntu/	priority:1
https://archive.ubuntu.com/ubuntu/	priority:2
https://security.ubuntu.com/ubuntu/	priority:3
```

Write /etc/apt/apt.conf.d/99-subathon-network with Acquire::Retries "1";
Acquire::http::Timeout "15"; Acquire::https::Timeout "15"; and
APT::Update::Error-Mode "any";. All existing trust/keyring/component/suite/architecture
settings stay intact. No proxies, hardcoded mirror addresses, third-party resolvers
or authentication bypass. Run checked sudo apt-get update with a 300-second process
deadline; configuration writes use 10-second deadlines. Both writes use text=True and stdout=DEVNULL (stderr stays visible).
main returns0 only after successful update, or reports "Ubuntu APT setup failed:"
on stderr and returns1 on RuntimeError, OSError or subprocess.SubprocessError,
including missing sudo, either tee failure/timeout and update failure/timeout. Existing job timeouts remain the overall bound.
Remove all 10 redundant old apt-get update calls, including both host-lane calls; keep all existing install/download
commands, exact package versions, hashes and ordinary test commands unchanged.

## Review decisions and external assumptions

Initial Claude Sonnet5.5 review at80de648 (report retained for the PR) identified
B1–B6 test safety/fidelity, exact command set, diagnostic evidence, guard oracles,
source layout and main exit coverage. Revised tests block alternate process APIs
and direct writes, strictly fixture the sole source-read path, emulate subprocess
check/text/capture behavior, and cover every refused/failed critical path.
No test is executed before separate Codex verification and Claude closing review.

APT's documented --error-on=any maps to APT::Update::Error-Mode; the upstream
[command-line mapping](https://github.com/Debian/apt/blob/main/apt-private/private-cmndline.cc)
and [Ubuntu24.04 manual](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html)
provide the source check. [GitHub's runner setup](https://github.com/actions/runner-images/blob/main/images/ubuntu/scripts/build/configure-apt-sources.sh)
already supplies archive/security fallbacks after Azure. This repair removes Azure
from selection rather than claim a fresh fallback architecture. It remains unproven
on hosted runners until actual CI: DNS, HTTPS CA roots, pocket availability and the
continued availability of existing exact package versions. Strict update also makes
third-party repository failures visible. The 300-second Python deadline bounds the
sudo invocation; a surviving child is still subject to the existing whole-job timeout
and GitHub runner cleanup. No tighter process-tree guarantee is claimed.

N1's proposed static copies of workflow pins/bodies are omitted: independent diff review
of all nine workflows plus their real hosted runs establish integration without new
baseline assertion duplication. Existing install/download and SDK/pin bytes must remain
identical, and reviewers compare them directly. N2–N6 are addressed by the sources,
explicit diagnostics/host guard/risks here. Only the implemented reviewed final head
will be pushed, so the local intended-red commit is not a hosted merge candidate.


### New incident evidence and revised mirror selection

After revision1 closing approval at b24ad5a but BEFORE any test execution, current
[GitHub runner-image incident15296](https://github.com/actions/runner-images/issues/15296)
and [incident15297](https://github.com/actions/runner-images/issues/15297) reported the
same failure across22.04/24.04/26.04 and all three ubuntu.com archive names.
[Canonical's status feed](https://status.canonical.com/rss), read directly on2026-11-11,
reported "DNS - Major Outage" since14:26UTC. Thus an Azure-only mirror removal is
insufficient evidence of recovery. No public-resolver override is justified by an
upstream authoritative DNS outage.

Revision2 prefers the [Linux Kernel Archives Ubuntu mirror](https://mirrors.kernel.org/)
outside that DNS domain, retaining Ubuntu's existing Signed-By keyring, mandatory
APT authentication and every exact package version/SDK hash. Numeric priority metadata
uses the same APT mirror-list format as GitHub's existing image. Canonical endpoints
remain lower-priority fallbacks. No new signing key or package/provider dependency.
Direct HTTP reads from the coordinator machine returned200 and PGP-signed metadata
headers for noble, noble-updates, noble-backports and noble-security at
https://mirrors.edge.kernel.org/ubuntu/; this does NOT certify signatures or hosted
access. Actual APT authentication/download and hosted checks remain mandatory.

The revised literal/source and diagnostic examples get a separate Codex review and
new independent Claude closing approval before first execution. Earlier approvals and
reports remain valid for unchanged isolation/error behavior and are preserved.
This is a requirement refinement from new incident evidence, not removal or weakening
of an existing observed-red assertion. New literal and all-ubuntu-DNS-failed examples
are independently derived here. Existing source-layout examples also gain missing-URI
and same-line mixed-URI refusal cases. No implementation or workflow has run yet.
