# CONTRACT-012 — Complete scene schema package and validation contract

Parent integration gate: [CONTRACT-008](CONTRACT-008.md). Kind: contract.
Authority: specification v0.45 §11, API-01/03, UI-01/02/03/04,
MEDIA-01/02/03/04/05/06. Status/owner/dependencies: progress/state.json.
Proposed prerequisites: CONTRACTPLAN-002, CONTRACT-009, CONTRACT-010 and CONTRACT-011.
See [ADR-0005](../decisions/0005-scene-contract-prerequisites.md).

## Preconditions and scope

Use actual integrated, differently reviewed scene, binding/time and asset/package
contracts and CONTRACT-005 primitives. Resolve every required vocabulary/reference;
an empty schema, arbitrary JSON escape hatch or unsupported-success placeholder
does not complete the package. Record an owning-domain gap rather than manufacturing
policy or omitting an element. Do not depend on parent 008/003 or downstream HTTP,
WS, SCENE, RENDER or viewer implementation; those consume the final package.

Before schema authoring, obtain actual review of schema dialect, common imports and
identifier/version layout, finite per-owning-field/message/input/output/decoded/
intermediate limits, cross-field semantic checks, validator/tool choice and pins.
No scene validator is currently selected. Existing OpenAPI 3.1 HTTP requirements
do not alone choose scene validation tooling or prove reference/dialect support.
Root owns dependency/build/CI changes; inspect actual primary tool documentation
and behavior for proposed capabilities instead of assuming a library can validate
everything. Routine engineering choices need review, not invented product policy.

## Acceptance

Produce the complete versioned scene schema package under assigned `schemas/scene/`
paths, referring to the single reviewed common vocabulary through root-coordinated
imports. Include all seven element families, geometry/layout/styles, bindings and
conditions, elapsed animation/timeline data, feature requirements, assets/fonts,
portable packages, drafts/live revisions and publication/restore boundary data.
Keep exact domain strings and opaque references distinct from geometry/text.
Specify unknown versions/features, rejected extra fields and compatibility rules
consistently with common005 and the owning contracts; schemas grant no authority.

Provide independently written complete valid/invalid examples, with required
coverage across the 009/010/011 logical examples, extrema, wrong types/references,
unsupported features/profiles, resource bounds and private/unknown field behavior.
Expected results cannot be generated by the decoder/renderer under test. Distinguish
schema-detectable defects from cross-field/domain/content/security checks that need
separate executable validation; document each checker responsibility and priority.

Any new executable checker/harness needs focused actual review and appropriate CI
before its result is evidence. Record selected tools/versions and exact observed
commands for reference resolution, complete positive/negative validation and
determinism where claimed. Generated clients/decoders and production behavior still
wait for their own reviewed tests, valid red, implementation and different source
review. No validator/compiler/codec is approved prospectively by this brief.

## Integration and ownership

Assign bounded artifact paths before editing; read root/schema AGENTS. Root owns
schema index/common imports, state/HTML/maps/build/CI/pins and integration. Review
actual complete schemas and independent examples before consumers. 008 separately
audits contract/schema consistency and required reference-scene coverage; HTTP006
continues to wait for 008, so imported scene shapes cannot remain unresolved.

The schema package does not prove authorization, durable publication/restore,
safe media decoding, font licensing, native/browser equivalence, editor behavior,
FPS, OBS or Windows/Linux support. All SCENE/RENDER/test-first/epic/release gates
remain. Record actual checks, CI coverage, limitations and next handoff, including
project consistency/current HTML/whitespace; follow [workflow](README.md).
