# CI-002 — Actionable setup failures and enforced merge checks

Kind: implementation. Specification v0.45 §§17–18. Depends on WORKFLOW-004, CI-001.
Contract: bounded-coordination-v2 §5; refine exact diagnostics/retry examples before
test authorship. Existing CI job names, pins, trust, admission and coverage remain.

Coordinator owns workflow/rules administration/docs/progress; test author owns
focused additive tests/tooling cases; fresh implementer owns tools/prepare_ubuntu_apt.py
and bounded reviewed acquisition/retry integration. Read scoped tools/tests instructions.

Report bounded stanza/field reasons and runner image identity before unsupported-layout
refusal. Keep refusal before configuration writes, authenticate acquisition and never
log credentials. Explicitly classify transient acquisition failures; at most one automatic
retry, preserving the first failure. Unknown layouts, signing/integrity, schema, build
and acceptance failures do not qualify. No caching, selective CI or failure suppression.

Review tests before execution, observe genuine intended red, then fresh implementation
and full independent code review. Run tooling and all affected actual hosted lanes.
Separately inspect live branch rules/check names, preserve unrelated protections and
configure required status checks matching the existing merge policy after current-head
success. Record/verify exact before/after settings. If access is unavailable, leave
that gate explicitly pending; never bypass protections or invent human approvals.
Publish a focused PR, merge normally and finish the workflow program before stopping.
