# CI-002 — Actionable setup failures and enforced merge checks

Kind: implementation. Specification v0.45 §§17–18. Depends on CI-001.
The owner-authorized program's bounded-coordination-v2 §5 supplies its forward
requirements, not a publication dependency. Author/review this task's standalone
exact diagnostics/retry contract before tests. It may land before WORKFLOW-004
when setup failures block that PR; existing full gates remain mandatory. Existing
CI job names, pins, trust, admission and coverage remain.

Coordinator owns workflow/rules administration/docs/progress; test author owns
focused additive tests/tooling cases; fresh implementer owns tools/prepare_ubuntu_apt.py
and bounded reviewed acquisition/retry integration. Read scoped tools/tests instructions.

Report bounded stanza/field reasons and runner image identity before unsupported-layout
refusal. Keep refusal before configuration writes, authenticate acquisition and never
log credentials. Use an explicit allowlist of transient acquisition signatures;
at most one automatic retry, preserving the first failure. Unclassified/mixed failures,
unknown layouts, signing/integrity, schema, build and acceptance failures do not
qualify. No caching, selective CI or failure suppression.

Review tests before execution, observe genuine intended red, then fresh implementation
and full independent code review. Run tooling and all affected actual hosted lanes.
Separately inspect live branch rules/check names, preserve unrelated protections and
configure required status checks matching the existing merge policy after current-head
success. Record/verify exact before/after settings. If access is unavailable, leave
that gate explicitly pending; never bypass protections or invent human approvals.
Derive the reviewed required list from every PR workflow job/matrix declaration
and actual current-head check contexts plus existing required external security
checks. Bind each context to its expected source app ID (GitHub Actions for Actions;
the actual security app for its check). Reject unrelated app/context substitutions.
Add/rename/remove workflows only with an explicit reviewed inventory/settings
update so obsolete names do not deadlock merges and new jobs do not silently drift.
Publish a focused PR, merge normally and finish the workflow program before stopping.
