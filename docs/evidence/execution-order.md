## Result and decisions

Execution order is the default, including in the generated HTML before JavaScript.
A stable topological traversal places every prerequisite before its dependent and
keeps source order as the tie-breaker among eligible independent nodes. Epics follow
their required children because they represent completion gates. The state array and
dependency graph are not reordered or rewritten.

The selector restores Epic grouping using source positions. The controller moves
the original nodes, preserving IDs, filters, expanded details and theme behavior.
The view description explains that independent tasks can proceed in parallel and
filters can hide prerequisites.

Computed availability requires a non-epic planned/ready task and all recorded
prerequisites done. Active, in-review, blocked and done tasks are excluded. Green
Dependencies complete badges, Ready to pick up and Next handoff use that same rule;
recorded statuses are not changed. No available task produces an explicit empty
handoff. This does not waive test/review, ownership or live/platform requirements.
