## Proposed design and scope reconciliation

Use an inert store on an already active existing session, with caller-owned real
commit/cleanup/publication. Initial/append success means complete STAGED values,
not durability. Exact initial duplicate/different conflict/stale/missing make no
own writes; known partial-write failures require actual rollback and unknown
outcomes keep existing fail-closed truth. Unlike existing source14's required
repository port, no owning transaction port exists in core plan capture, so this
proposal does not add one unnecessarily.

Propose one immutable plan/event/header plus immutable scalar revision rows and
three ordinal child collections (rules/modifiers/requested effects). Header reuses
the actual immutable receipt projection, retaining event ancestry/optional link
and one head; no plan-per-receipt uniqueness or new numerical surrogate. Root owns
the actual five-table physical decision, constraints and immutable-prefix4 review.

Important explicitly resolved design boundaries, sent as preliminary milestones
to root (not approvals of this actual document):

- Pure numeric codec0..MAX is distinct from persisted revision/head/parent1..MAX.
  Full ApplicationPlan never starts high or skips revisions. A separate targeted
  CapturedPlanRevision snapshot has explicit local/selected validation scope, not
  certification of a complete ApplicationPlan or permission to append/apply.
- The proposed sparse MAX SQL fixture is deliberately incomplete: actual selected
  MAX/localparent/header/init markers prove typed full-range SQL fidelity, while
  full aggregate read and append must refuse its count/head gap. No tiny seed,
  mocked count or successful MAX allocation is claimed to be a valid1..MAX history
  or a reachable real-chain exhaustion test. Real-chain resource limits are honest.
- Full materialization caps do not become append/history quotas. Append audits
  actual complete structural-chain/capture-valuation metadata in bounded pages
  and one bounded new revision; old child payloads not examined are not claimed
  checked. Every query still consumes existing cumulative writer budgets. Complete
  reads strictly validate all returned bodies, ordinals and canonical components.
- Exact is canonical cpp_rational VALUE: signed numerator and positive reduced
  denominator ASCII BLOBs, zero0/1, no REAL/int64 conversion or rerounding. Decimal
  source spellings are separate unchanged fields. Proposed component16384-byte
  bounds are independent from parser512/256/finalizer4096-bit policies and do not
  promise infinite resources. Values beyond4096bits within storage bounds remain.
- Actual physical source references are separate from semantic refs whose physical
  namespace/resolver has never been agreed. No fake config FK/authorization proof
  is added for rule/action/modifier/quote/actor/event ancestry strings. Upstream
  retained-meaning preconditions and unfinished evaluator/permission/resolver gates
  remain explicit, not waived or reported implemented by byte storage.
