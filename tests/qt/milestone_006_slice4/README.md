## Owner entry mapping

Each stub may become one mechanical forwarding call to a named owning
server entry. A fixture must not enact publication, select the current
configuration, build a disclosure result, infer a format, or issue a
confirmation token on behalf of the product. Review the forwarding body
and owning entry together while preserving inputs and assertions.

- `publish_definitions` maps to the milestone configuration owner entry
  `publish_milestone_definitions`. The supplied definition authority resolves
  the proposed revision and returns the admitted immutable definition facts.
  The protected `ReferenceConfigurationArchive` can resolve existing
  immutable startup versions but has no editor or current-publication
  operation. Retained context storage is an archive. Neither bypasses the
  missing serialized owner publication. No new definite durable encoding is
  imposed by the fixture.
- `capture_later_group` maps to `capture_published_milestone_group` on the
  normal milestone capture owner. It receives an owned exact synthetic
  receipt, typed origin and crossing operands. The fixture supplies no
  chosen future action, sender, payload, or revision to this call. Product
  publication and capture require separate normal writer turns. The fixture
  verifies the later bundle and enrolled job through existing owning reads.
- `preview_disclosure` maps to `preview_milestone_replacement_disclosure`
  on the milestone interruption command owner. `CommandAuthority::select`
  resolves current command/disclosure facts. The owner profile qualifies
  compatibility against the exact original `DeliveryJobKey` and verified
  original format. Current authority supplies the proposed sender-selection
  mode. The mechanical view projection uses exact typed slot identity, action
  and payload or bonus, release and Hold gates, and the opaque protected
  confirmation. Protected storage holds the original format in
  `ApplicationJobIntent::envelope` and the exact replacement chain,
  payload/route/sender in v21. `AuthorizedCapture` and opaque
  `ReplacePreview` do not expose current mode or ordered disclosure today.
  No test decodes or changes a v21 BLOB to provide them. The exact current
  authority and compatibility checks need source review. The protected
  delivery profile uses one valid original format, so a fabricated alternate
  original format would be an invalid fixture. The incompatible and
  unproved rows exercise the profile gate instead.
